# Development progress

## Implemented and locally verified

- Windows Python package/CLI, YAML configuration, encrypted SQLCipher storage with DPAPI-protected key, persistent text sessions, transcript listing/show/resume, and provider adapter.
- Text/Markdown import and user-confirmed audio-file transcription with content-hash duplicate detection, conservative verbatim candidates, and explicit provider-backed semantic extraction from imported documents or user messages. Raw audio is not retained. Extracted candidates require exact evidence quotes, persist multi-source provenance, remain pending review, link normalized exact duplicates with audit events, and support approval/rejection, weighted FTS retrieval, correction, and source deletion with evidence-link propagation.
- CBT/schema/auto prompt policies and in-session `/method` switching; configurable estimated-token budgets bound safety/method instructions, separately labeled profile/memory evidence, and chronologically continuous recent turns, with the current user turn last. Truncation markers are included within the estimates.
- JSON export and explicit local-data deletion command; documentation for architecture, memory, voice, privacy, safety, decisions, testing, and progress.
- Tests use an injected fake provider for CLI session continuity; Windows integration coverage includes memory lifecycle.
- A Windows-only text-path E2E test now connects the workflow from a synthetic 3,000-word import through mocked source-quoted extraction, explicit candidate review, correction/profile generation, Auto-to-CBT conversation retrieval, process-exit persistence, resumed-context retrieval, transcript persistence, and deletion of source, memories, and derived profiles. This is a deterministic rehearsal, not live-provider or personal-essay acceptance.
- Experimental voice path now uses faster-whisper (local CPU) for VAD-completed utterances and Piper (local CPU) for speech synthesis. Model weights are downloaded separately into the local data directory; user audio is not sent to those model hosts or DeepSeek. The Whisper adapter is utterance-batched, not streaming, so partial captions are no longer claimed. DeepSeek is the default text-only provider. The previous OpenAI Realtime transcription and OpenAI TTS adapters were removed from the runtime path. Voice model/device acceptance still requires a real user-spoken run.
- Memory review supports user-proposed relationship annotations and explicit, audited evolution: accepting a possible-contradiction link does not suppress either record; a confirmed evolution approves the newer sourced candidate and marks the older approved memory superseded without deleting its provenance.
- `psyche memory profile` writes a versioned deterministic profile from approved atomic memories, records contributing IDs, invalidates the current snapshot when relevant memory/relation state changes, and adds a current profile to LLM context as untrusted evidence. Retrieval uses configurable weighted FTS ranking; weights/scoring are not clinically calibrated.
- Cloud-dependent conversation sessions and memory extraction honor `privacy.cloud_processing_allowed`; with cloud disabled, session start/resume stops before provider initialization, while local audio transcription/import remains available. Conversation context has separate configurable approximate-token limits for policies, profile, retrieved memories, and recent history.
- Safety rules now use bounded intent patterns instead of substring-matching every mention of diagnosis; a few explicit imminent-harm forms, straightforward negations, streamed-provider bypass behavior, and prompt-level behavioral constraints have deterministic tests. This remains a deliberately narrow phrase baseline, not contextual risk detection or clinical validation.
- Added an offline conversation-style evaluation harness and eight curated ordinary, methodology, correction, injection, and trauma scenarios. It reports word-count/question-count proxies and flags repeated greetings/canned phrases; qualitative criteria remain for human review. It makes no provider calls. Prompts now align ordinary responses with the plan's 15–55-word target while discouraging canned praise and repeated introductions.
- Provider failures now avoid chaining SDK exceptions that might contain credentials or response data. Regression tests inspect formatted failures, and an orchestrator test inspects the bounded payload passed to a fake provider; real HTTP payload inspection, full log-leakage audit, and provider-side behavior remain unverified.
- Storage-security regressions now verify fail-closed database initialization when key setup fails and, on Windows, verify a synthetic private marker is not plaintext-readable from the SQLCipher database. This is narrow test coverage, not completion of the full security audit.
- Memory lifecycle integration coverage now verifies deleting one of multiple independent evidence sources preserves the supported memory, while deleting the final source removes it from active retrieval and purges stored profile snapshots that derived from it.

## Milestone gates and end-to-end plan

- Milestone 1 text-session gate: verified by encrypted storage smoke test and CLI fake-provider start/exit/resume/end integration test.
- Memory limitations: possible contradictions are not discovered automatically; relation creation, review, and evolution are explicit user actions. Model-generated summaries, active-context updates, transcript-redaction propagation, and clinical calibration of retrieval ranking remain outstanding.
- Milestone 2 voice gate: **in progress/not passed**. Continuous local capture/VAD, local utterance-batched faster-whisper STT, local Piper TTS, streamed DeepSeek text generation, conservative spoken-sentence-prefix recovery, and a CLI recovery choice are implemented. STT partials, token-to-audio synthesis, and echo cancellation are not implemented. Local model inference, intelligibility, physical microphone/speaker validation, latency, and the 30-minute run remain outstanding.
- Milestone 3 methodology: prompt-level CBT/schema/auto guardrails and switching implemented; an offline curated evaluation harness is now available, but real responses have not yet been scored and the methodology quality gate is not passed.
- Milestone 4 memory: provider-backed source-quoted extraction, deterministic normalized exact-link consolidation, multi-source provenance, user-reviewed relation/evolution handling, deterministic versioned profile generation/injection, and configurable weighted FTS retrieval are implemented alongside review/search/correction/deletion. Automatic semantic relation detection, calibrated weights, and complete derived-data propagation remain incomplete. Gate not passed.
- Milestone 5 ingestion: UTF-8 text/Markdown import, confirmed audio-file transcription, duplicate detection, and opt-in semantic extraction implemented. Essay-driven recall acceptance remains incomplete. Gate not passed.
- Text E2E preflight: deterministic workflow through import, memory review/correction, retrieval, transcript persistence, and deletion passes with mocked providers. This narrows integration risk but does not satisfy the live-voice end-to-end acceptance scenario.
- Milestone 6 hardening: provider exception sanitization, bounded-payload assembly, fail-closed encryption initialization, and plaintext-read resistance now have targeted regression coverage. Adversarial safety evaluation, complete log/leakage/deletion audit, real HTTP payload inspection, and clinical review are still not performed; gate not passed.

The complete end-to-end POC is **not complete**. The formal acceptance checklist is now 4/16: Windows editable install, encrypted storage initialization, the full automated suite, and starting a live Auto voice session with a final transcript and response. The reported live session had an audio cutoff, and the subsequent playback-protection fix has not yet been retested on hardware. The user's mic/VAD diagnostic is a local diagnostic, not a substitute for live acceptance. Remaining gates include the private essay scenario, transcript persistence across restart, local playback acceptance, latency and 30-minute voice checks, interruption/method-switch checks, conversational quality thresholds, and independent clinical review. No claim of clinical efficacy or crisis-detection reliability is made.

## Known defects and deferred work

- Safety phrase rules are deliberately narrow and not a dependable risk classifier.
- Memory search uses FTS candidates with a configurable heuristic ranking; its weights are not calibrated. Semantic extraction is explicit and review-only, and consolidation is exact-match only. Context token sizing is a conservative character estimate rather than provider tokenizer accounting.
- Voice remains experimental; spoken-prefix recovery is conservative at complete sentence boundaries. Local Whisper runs after the utterance, not incrementally; echo cancellation, token-to-audio synthesis, and live acceptance remain absent. Local model inference and audio-file transcription still need acceptance tests.
- Voice playback now ignores detected microphone speech while Psyche is speaking to prevent echo-driven cutoffs. This is intentionally half-duplex: users must wait for playback to finish; user interruption during playback is not implemented and the plan's barge-in requirement remains unmet.
- Prompt style improvements have only prompt-contract tests; the new offline evaluation harness has not yet been populated with real responses. It cannot judge empathy, clinical appropriateness, or safety.
- No transcript retention policy, provider payload inspection/redaction, portable key migration, secure physical erasure, or provider-side deletion.
- Manual validation of target hardware and usable DeepSeek text-API access is required; the earlier OpenAI test was rejected before model execution due to insufficient credits.
