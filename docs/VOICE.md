# Voice status

The voice implementation includes typed voice events/state, continuous microphone capture and local WebRTC VAD, incremental OpenAI Realtime transcription while VAD captures an utterance, streamed LLM text split into sentence-sized TTS requests, bounded streamed PCM playback, and a turn coordinator. Microphone capture negotiates a supported device format, downmixes multichannel microphone arrays, and resamples to the 16 kHz mono PCM frames expected by VAD. Realtime transcription declares the required 24 kHz PCM format and resamples microphone frames incrementally. Playback checks a selected output's support for 24 kHz, falls back to its reported native rate when needed, and resamples with retained state. Start the experimental mode with `psyche session start --mode voice` after `pip install -e '.[voice]'` and configuring provider credentials. Partial captions are emitted during capture; the final transcript is sent to the conversation engine after VAD closes the turn. New VAD speech onset cancels active generation/playback. Assistant text is committed as delivered only after playback completes. On interruption or synthesis/playback failure, only whole sentences whose final audio chunk was written are stored, marked `interrupted` or `incomplete`; generated or partly played later text is omitted. Raw PCM is not retained.

This is a working but **experimental** voice path, not a passed live-voice milestone. Capture/VAD remain active during response generation and playback. The LLM is streamed, then text is buffered to sentence boundaries before separate TTS requests; this is not token-to-audio synthesis. Text may appear in the terminal before it is spoken, but only confirmed spoken sentence prefixes are saved as interrupted/incomplete delivery. On a voice error, the CLI offers retry-listening, switch-to-text in the same session, or end-and-save. There is no acoustic echo cancellation; headphones are recommended to reduce speaker-triggered false barge-ins. A hardware investigation found that Windows exposes the Intel microphone array as 48 kHz / 4-channel on WASAPI, a format the previous 16 kHz / mono-only capture could not open.
