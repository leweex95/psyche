# Memory system

The encrypted SQLCipher database stores imported UTF-8 documents/transcripts and atomic memory candidates. Plain text import performs conservative extractive segmentation (verbatim sentences of at least 35 characters); optional model-based extraction is a separate explicit command and does not claim clinical significance. Every candidate is pending by default and includes a source ID, source type, and character-offset span. Existing databases receive provenance fields through additive migrations. Normalized exact duplicates are linked rather than inserted twice.

`psyche memory extract --document-id ID` or `--session-id ID` explicitly sends the selected source (or only the session's user messages) to the configured provider for semantic candidate extraction. Every candidate must include an exact, locally verified quote; fabricated/unsupported quotes are discarded. Model output is validated before writing, and all new candidates remain pending for user review. Normalized exact matches to pending/approved records add an auditable evidence link; rejected candidates are not silently revived. Candidate records can link to multiple evidence sources, including specific messages or character spans. Provider-side processing/retention is outside this application's control.

`psyche memory review` approves or rejects candidates. Only approved FTS5 matches can enter retrieval. Matches are ranked with a deterministic heuristic using lexical relevance, importance, epistemic/source evidence, recency, and methodology-category fit. Defaults in `config/default.yaml` use weights 0.40/0.25/0.15/0.10/0.10; weights are configurable and normalized. A high-importance record is elevated only when it directly matches the query. This is an engineering heuristic, not clinically calibrated ranking. The methodology and system prompt identify memories as evidence, not instructions. Corrections mark a record user-confirmed and are recorded in `memory_events`; rejection/deletion removes it from active retrieval. Use `psyche memory forget ID --delete-source` to delete linked imported documents or session messages. Shared evidence links are removed; another memory remains active only if it still has independent source evidence. Without that flag, source history remains by design.

Possible contradictions are not inferred or resolved automatically. Use `psyche memory relate NEW_ID OLD_ID` to add a pending human-review annotation (or `--type related` for a non-contradiction relationship), then `psyche memory review-relations` to accept or dismiss it. Accepting a relation does not hide either memory. To explicitly record that a newer memory replaces an older approved one, run `psyche memory evolve NEW_ID OLD_ID`; after confirmation, the new sourced item is approved and the older item is marked `superseded`, with both statements, sources, and audit events retained. Evolution requires both memories to have evidence and belong to the same category. A relation annotation alone is not evidence that claims conflict or that one is newer.

`psyche memory profile` creates a versioned, deterministic summary from approved atomic memories only, with a 6,000-character bound on included memory text. Each section item carries its memory ID, and the stored version records the exact set of contributing IDs. Unavailable categories are shown as “None recorded”; the profile does not infer current concerns or exercises from unrelated categories. A possible-contradiction annotation is surfaced only as unresolved comparison context and does not decide which statement is true. Approval, correction, supersession, and relation review invalidate the current profile; deleting a memory also removes any stored profile version that included it. Run the command again to create a fresh version. When current, the profile and selected memories are separately labeled, budget-bounded context data, not system instructions or an independent source of truth.

Limitations: consolidation is limited to deterministic normalized exact matches plus user-directed relation and evolution review; there is no automatic semantic contradiction/evolution detection, active-context update, transcript-redaction propagation, or clinical calibration of the ranking heuristic. Model candidates are review-only; this feature has not been validated for clinical accuracy.
